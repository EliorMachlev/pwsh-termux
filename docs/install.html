Install guide

Install

Add the repository once, then pkg installs and updates PowerShell like any other package.

Before you start

You need Termux on a 64-bit Arm phone (arm64, also written aarch64), about 200 MB of free space (the download is about 50 MB) and an internet connection. Check the architecture; the answer must be aarch64:

uname -m

Step 1

Set up the repository (once)

Stable and preview both need this. The command enables Termux’s glibc repository, installs pwsh-termux-keyring (the repository’s public signing key and its apt source) and refreshes the package lists. The key goes to $PREFIX/share/keyrings/, not to apt’s global trust store, and the source names it with signed-by, so apt trusts it for this repository only. pkg then checks every later download against it.

pkg install -y glibc-repo && \
curl -fsSL https://pwsh-termux.machlev.org/pwsh-termux-keyring.deb -o "$TMPDIR/pwsh-termux-keyring.deb" && \
dpkg -i "$TMPDIR/pwsh-termux-keyring.deb" && \
pkg update

Tap or click a command once to select all of it, then copy it.

The versions the repository serves now are in its releases.

Prefer not to install a package for the key? Add it by hand.

Step 2

Stable: the regular install

Pick this unless you know you want the preview. pwsh is the highest stable PowerShell 7 release. The command is pwsh.

pkg install pwsh

Start it and print its version:

pwsh
$PSVersionTable.PSVersion

Step 3, optional

Preview: the optional early build

pwsh-preview is the newest preview or release candidate. Expect rough edges.

  • It exists only while Microsoft’s newest preview is newer than the newest stable release. When none qualifies, pkg install pwsh-preview fails with Unable to locate package.
  • It installs next to pwsh, as its own command, and shares no files with it. You can have both.
  • It never turns into stable. When the final release ships, previews of that version leave the repository; install pwsh.

See what is on offer now:

apt-cache policy pwsh pwsh-preview

Install and start it:

pkg install pwsh-preview
pwsh-preview

Update

pkg upgrade updates everything, including pwsh, pwsh-preview and the keyring.

pkg upgrade

The repository is re-signed every day even when nothing changed, so most days pkg update only downloads the small, freshly signed InRelease file. A new PowerShell version is picked up by the next daily run after Microsoft releases it.

Uninstall

pkg remove pwsh
pkg remove pwsh-preview    # only if installed
pkg remove pwsh-termux-keyring
pkg update

The first line removes PowerShell. Remove pwsh-preview only if you installed it: apt stops with an error for a package it does not know. The third line removes the key and the apt source, so pkg stops contacting this site. If you added them by hand, delete the two files yourself:

rm "$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg" "$PREFIX/etc/apt/sources.list.d/pwsh-termux.list"

Your profile and modules in ~/.config/powershell and ~/.local/share/powershell stay. Delete them for a clean slate.

Verify it yourself

Optional. You do not have to take this page’s word for any of it. Each check uses a different channel, so a mismatch between them is itself a warning sign.

1. The signing keys

The keyring holds two keys. The first signs the repository; the second is an offline recovery key that only signs to move users to a new key if the first is ever lost or stolen. Compare both fingerprints with the security policy on GitHub, or with the FINGERPRINT.txt attached to each release:

Signing key
7086 C70B 4A25 576F E0C0 CE77 E43F B41F 02D0 1FC8
Recovery key
937A 3D41 5103 CFF8 9DCD A982 A4B4 5397 EEB6 D752

To print them from the installed file:

pkg install gnupg
gpg --show-keys "$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg"

2. Where the packages were built

Every .deb, including pwsh-termux-keyring.deb, has a signed build provenance from this project’s build workflow, recorded on GitHub. With the GitHub CLI (pkg install gh, signed in), these are the checks the publishing workflow itself runs before it signs anything:

gh attestation verify "$TMPDIR/pwsh-termux-keyring.deb" \
  --repo EliorMachlev/pwsh-termux \
  --signer-workflow EliorMachlev/pwsh-termux/.github/workflows/build-packages.yaml \
  --deny-self-hosted-runners

The same command works for a pwsh_<version>_aarch64.deb downloaded from a release, and for its SBOM files.

3. The signed index

pkg already does this on every update: it checks InRelease against the key, then the package list against InRelease, then each package against the list. To see it by hand:

curl -fsSL https://pwsh-termux.machlev.org/dists/stable/InRelease -o "$TMPDIR/InRelease"
gpgv --keyring "$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg" "$TMPDIR/InRelease"
grep -E '^(Date|Valid-Until):' "$TMPDIR/InRelease"

Valid-Until is 14 days after Date. The repository is re-signed every day, so an old index cannot be served to you for more than 14 days without apt refusing it.

The project’s security contact is in /.well-known/security.txt, which points to the security policy.

Add the key by hand instead

If you would rather not install a package for it, these commands write the same two files with the same content, then install stable. Stable needs Termux’s glibc repository, so the first line enables it:

pkg install -y glibc-repo
mkdir -p "$PREFIX/share/keyrings"
curl -fsSL https://pwsh-termux.machlev.org/pwsh-termux.gpg \
  -o "$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg"
echo "deb [signed-by=$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg] https://pwsh-termux.machlev.org stable main" \
  > "$PREFIX/etc/apt/sources.list.d/pwsh-termux.list"
pkg update
pkg install pwsh

A key added by hand is not updated by pkg upgrade. When the key is rotated, download it again (the security policy announces it), or install the keyring package.

What happens when the signing key changes?

If you installed with the commands above, nothing for you to do. A planned rotation ships the next key in a new pwsh-termux-keyring while the old key still signs, for 180 days; pkg upgrade lists pwsh-termux-keyring among the upgrades, and that is all you see. If the signing key is ever lost or stolen, a security advisory is published on GitHub, the repository is signed once with the offline recovery key that your keyring already trusts, and again pkg upgrade installs the new keyring. Either way, check the new fingerprints against the security policy if you like.

If something goes wrong

  • NO_PUBKEY, or the repository is not signed. The key is missing, empty or outdated. A key added by hand is not updated by pkg upgrade, and a device that misses a whole 180-day rotation window keeps only the old key. Run the set-up command again; if you added the key by hand, download it again and check the file is not an error page. Then compare the fingerprints.
  • Unable to locate package pwsh. The keyring package is not installed (the source line comes with it), or pkg update was not run afterwards. Repeat the set-up.
  • Unable to locate package pwsh-preview. No preview is newer than stable right now. That is normal; see preview.
  • depends on glibc, but it is not installable. The glibc repository is not enabled. Run pkg install glibc-repo, then pkg update.
  • Unable to locate package glibc-repo. Termux’s own package lists are old or point to an outdated mirror. Run pkg update (or termux-change-repo), then the set-up again.
  • No installation candidate, or dpkg says package architecture (aarch64) does not match system. The device is not arm64. uname -m must print aarch64; a 32-bit Termux (armv7l, armv8l) or an x86 device cannot run these packages. On a 64-bit phone, check that Termux itself is the 64-bit (arm64-v8a) build: dpkg --print-architecture prints aarch64.
  • Release file for https://pwsh-termux.machlev.org/dists/stable/InRelease is expired. The signed index is valid for 14 days and is re-signed daily. If the project’s build has been broken for longer than that, apt refuses the old index instead of quietly serving stale packages; PowerShell keeps working, and updates resume once the index is re-signed. Your device’s clock may also be far ahead: check the date in Android’s settings. If it lasts more than a day or two, check the issues.
  • Release file … is not valid yet. Your device’s clock is behind. Set the date and time automatically in Android’s settings.
  • pwsh says it cannot execute, or a library is missing. Reinstall it. If that fails, open an issue with the output of the second command.
pkg install --reinstall pwsh
pkg list-installed | grep -E 'glibc|icu|pwsh'

Turn off Microsoft’s telemetry

This package does not change PowerShell. Microsoft’s build collects usage telemetry unless you opt out, and it can print a notice about newer versions. To turn both off, append this to ~/.bashrc (or your shell’s startup file) and export them in the current shell, which does not re-read that file:

echo 'export POWERSHELL_TELEMETRY_OPTOUT=1' >> ~/.bashrc
echo 'export POWERSHELL_UPDATECHECK=Off' >> ~/.bashrc
export POWERSHELL_TELEMETRY_OPTOUT=1
export POWERSHELL_UPDATECHECK=Off
