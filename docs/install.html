Install

One line, then pkg keeps PowerShell up to date.

Requirements

  • Termux on an arm64 (aarch64) device. Check with uname -m.
  • The Termux glibc repository, which provides the glibc libraries PowerShell needs. The line below enables it.
  • About 200 MB of free space (the package is about 50 MB to download).

Install

pkg install -y glibc-repo && \
curl -fsSL https://pwsh-termux.machlev.org/pwsh-termux-keyring.deb -o $TMPDIR/pwsh-termux-keyring.deb && \
dpkg -i $TMPDIR/pwsh-termux-keyring.deb && \
pkg update && pkg install pwsh

Tap or click the command once to select all of it, then copy it.

The versions the repository serves now are in its releases.

The second command downloads pwsh-termux-keyring, a small package with the repository’s public signing key and its apt source. The key goes to $PREFIX/share/keyrings/, not to apt’s global trust store, and the source names it with signed-by, so apt trusts it for this repository only. pkg then checks every later download against it; pkg remove pwsh-termux-keyring undoes it. Then run it:

pwsh
$PSVersionTable.PSVersion

For the preview channel, pkg install pwsh-preview installs pwsh-preview next to pwsh. It only exists while Microsoft’s newest preview is newer than the newest stable release.

Verify it yourself

You do not have to take this page’s word for any of it. Each check below uses a different channel, so a mismatch between them is itself a warning sign.

1. The signing keys

The keyring holds two keys. The first signs the repository; the second is an offline recovery key that only signs to move users to a new key if the first is ever lost or stolen. Compare both fingerprints with the security policy on GitHub, or with the FINGERPRINT.txt attached to each release:

7086 C70B 4A25 576F E0C0  CE77 E43F B41F 02D0 1FC8   signing key
937A 3D41 5103 CFF8 9DCD  A982 A4B4 5397 EEB6 D752   recovery key

To print them from the installed file:

pkg install gnupg
gpg --show-keys $PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg

2. Where the packages were built

Every .deb, including pwsh-termux-keyring.deb, has a signed build provenance from this project’s build workflow, recorded on GitHub. With the GitHub CLI (pkg install gh, signed in), these are the checks the publishing workflow itself runs before it signs anything:

gh attestation verify $TMPDIR/pwsh-termux-keyring.deb --repo EliorMachlev/pwsh-termux \
  --signer-workflow EliorMachlev/pwsh-termux/.github/workflows/build-packages.yaml \
  --deny-self-hosted-runners

The same command works for a pwsh_<version>_aarch64.deb downloaded from a release, and for its SBOM files.

3. The signed index

pkg already does this on every update: it checks InRelease against the key, then the package list against InRelease, then each package against the list. To see it by hand:

curl -fsSL https://pwsh-termux.machlev.org/dists/stable/InRelease -o $TMPDIR/InRelease
gpgv --keyring $PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg $TMPDIR/InRelease
grep -E '^(Date|Valid-Until):' $TMPDIR/InRelease

Valid-Until is 14 days after Date. The repository is re-signed every day, so an old index cannot be served to you for more than 14 days without apt refusing it.

The project’s security contact is in /.well-known/security.txt, which points to the security policy.

Add the key by hand instead

If you would rather not install a package for it, these commands write the same two files with the same content:

mkdir -p $PREFIX/share/keyrings
curl -fsSL https://pwsh-termux.machlev.org/pwsh-termux.gpg \
  -o $PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg
echo "deb [signed-by=$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg] https://pwsh-termux.machlev.org stable main" \
  > $PREFIX/etc/apt/sources.list.d/pwsh-termux.list
pkg update
pkg install pwsh

A key added by hand is not updated by pkg upgrade. When the key is rotated, download it again (the security policy announces it), or install the keyring package.

Update

pkg upgrade            # updates everything, including pwsh and the key package

Most days a pkg update downloads only the small, freshly signed InRelease file: the repository is re-signed daily even when nothing changed, and nothing is offered for upgrade until Microsoft releases a new version.

Uninstall

pkg remove pwsh pwsh-preview     # PowerShell (either or both)
pkg remove pwsh-termux-keyring   # the key and the apt source
pkg update

Removing pwsh-termux-keyring deletes both $PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg and $PREFIX/etc/apt/sources.list.d/pwsh-termux.list, so pkg stops contacting this site. If you added them by hand, delete those two files yourself. Your PowerShell profile and modules in ~/.config/powershell and ~/.local/share/powershell are yours and stay; delete them too if you want nothing left.

Questions

What happens when the signing key changes?

If you installed with the line above, nothing for you to do. A planned rotation ships the next key in a new pwsh-termux-keyring while the old key still signs, for 180 days; pkg upgrade lists pwsh-termux-keyring among the upgrades, and that is all you see. If the signing key is ever lost or stolen, a security advisory is published on GitHub, the repository is signed once with the offline recovery key that your keyring already trusts, and again pkg upgrade installs the new keyring. Either way, check the new fingerprints against the security policy if you like.

And if I added the key by hand, or did not update for months?

A key added by hand is not updated by pkg upgrade, and a device that misses a whole 180-day window keeps only the old key. You then see NO_PUBKEY or not signed from pkg update. Run the install line again (or download the key again), and compare the fingerprints above.

Why did pkg update say the Release file is expired?

The repository’s signed index is valid for 14 days and is re-signed daily. If the project’s build has been broken for longer than that, apt refuses the old index instead of quietly serving stale packages. PowerShell keeps working; updates from this repository resume once the index is re-signed. If it lasts more than a day or two, check the issues.

If something goes wrong

SymptomCause and fix
pkg update says NO_PUBKEY or the repository is not signedThe key is missing, empty or outdated (for example after a key change you missed). Run the install line again; if you added the key by hand, download it again and check the file is not an error page. Then compare the fingerprints.
Unable to locate package pwshThe keyring package is not installed (the source line comes with it), or pkg update was not run afterwards.
depends on glibc, but it is not installableThe glibc repository is not enabled: pkg install glibc-repo, then pkg update.
Unable to locate package glibc-repoTermux’s own package lists are old or point to an outdated mirror: run pkg update (or termux-change-repo), then the install line again.
pkg install pwsh finds no installation candidate, or dpkg says package architecture (aarch64) does not match systemThe device is not arm64. uname -m must print aarch64; a 32-bit Termux (armv7l, armv8l) or an x86 device cannot run these packages. On a 64-bit phone, check that Termux itself is the 64-bit (arm64-v8a) build: dpkg --print-architecture prints aarch64.
Release file for https://pwsh-termux.machlev.org/dists/stable/InRelease is expiredThe signed index was not renewed within its 14 days (see above), or your device’s clock is far ahead: check the date in Android’s settings. Otherwise nothing to fix on your side; it clears with the next re-sign.
Release file … is not valid yetYour device’s clock is behind. Set the date and time automatically in Android’s settings.
Installed but pwsh says it cannot execute or a library is missingRun pkg install --reinstall pwsh; if it persists, open an issue with the output of pkg list-installed | grep -E 'glibc|icu|pwsh'.

About PowerShell’s own behavior

This package does not change PowerShell. Microsoft’s build collects usage telemetry unless you opt out, and it can print a notice about newer versions. To turn both off, add to ~/.bashrc (or your shell’s file):

export POWERSHELL_TELEMETRY_OPTOUT=1
export POWERSHELL_UPDATECHECK=Off
