Verify it yourself

You do not have to take this site’s word for it. Each check uses a different channel, so a mismatch between them is itself a warning sign.

1. The signing keys

The keyring holds two keys: the one that signs the repository, and an offline recovery key that only signs to move users to a new key if the first is lost or stolen. Compare both fingerprints with the security policy or the FINGERPRINT.txt on each release:

Signing key
7086 C70B 4A25 576F E0C0 CE77 E43F B41F 02D0 1FC8
Recovery key
937A 3D41 5103 CFF8 9DCD A982 A4B4 5397 EEB6 D752

Print them from the installed file:

pkg install gnupg
gpg --show-keys "$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg"

2. Where the packages were built

Every .deb has a signed build provenance from this project’s build workflow, recorded on GitHub. With the GitHub CLI (pkg install gh, signed in), run the checks the publishing workflow runs before it signs anything:

gh attestation verify "$TMPDIR/pwsh-termux-keyring.deb" \
  --repo EliorMachlev/pwsh-termux \
  --signer-workflow EliorMachlev/pwsh-termux/.github/workflows/build-packages.yaml \
  --deny-self-hosted-runners

The same works for a pwsh_<version>_aarch64.deb from a release, and for its SBOMs.

3. The signed index

pkg checks InRelease against the key, the package list against InRelease and each package against the list on every update. To see it by hand:

curl -fsSL https://pwsh-termux.machlev.org/dists/stable/InRelease -o "$TMPDIR/InRelease"
gpgv --keyring "$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg" "$TMPDIR/InRelease"
grep -E '^(Date|Valid-Until):' "$TMPDIR/InRelease"

Valid-Until is 14 days after Date and the index is re-signed daily, so apt refuses an old index served to you for longer than that. The security contact is in /.well-known/security.txt.

Add the key by hand

These commands write the same two files as the keyring package, then install stable:

pkg install -y glibc-repo
mkdir -p "$PREFIX/share/keyrings"
curl -fsSL https://pwsh-termux.machlev.org/pwsh-termux.gpg \
  -o "$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg"
echo "deb [signed-by=$PREFIX/share/keyrings/pwsh-termux-archive-keyring.gpg] https://pwsh-termux.machlev.org stable main" \
  > "$PREFIX/etc/apt/sources.list.d/pwsh-termux.list"
pkg update
pkg install pwsh

pkg upgrade does not update a key added by hand. After a rotation, download it again or install the keyring package.

When the signing key changes

If you installed with the keyring package, nothing to do: pkg upgrade brings the new keyring.

  • Planned rotation. The next key ships in a new keyring while the old key still signs, for 180 days.
  • Lost or stolen key. A security advisory is published on GitHub and the repository is signed once with the offline recovery key your keyring already trusts.

Either way, you can check the new fingerprints against the security policy.
